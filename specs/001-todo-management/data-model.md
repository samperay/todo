# Data Model: Basic Todo Management

Persistence shapes live in SQLAlchemy models. API shapes live in Pydantic schemas. They are not the same types. `owner_id` is stored and never returned on a todo.

The local engine is SQLite. Column types are portable SQLAlchemy types so a later URL change does not rewrite these fields. The schema is created with `Base.metadata.create_all()` in database infrastructure. There is no migration revision in this version.

## Person

An identified caller. Created by `POST /api/v1/users`. The same token resolves to the same person.

| Field | Storage | API | Rules |
|-------|---------|-----|-------|
| id | UUID, primary key, portable type | Returned once at creation, and not required on later calls | Generated by the service. Never reused. |
| token_hash | string, unique, not null | Never returned | Hash of the one-time bearer token. The plaintext token is returned only from create-user. |
| created_at | UTC datetime, not null | Not part of the todo contract | Set by the application when the person is created. |

Relationships: a person owns zero or more todos. There are no roles.

## Todo

One piece of work owned by exactly one person.

| Field | Storage | API | Rules |
|-------|---------|-----|-------|
| id | UUID, primary key, portable type | Read-only on responses | Generated by the service. The client cannot send it. Never reused after delete. |
| owner_id | UUID, not null, foreign key to person.id | Omitted | Set to the creator. Never updated. Indexed. |
| title | string, not null, max 200 | Required on create. Optional on patch. | Must contain a non-whitespace character. Whitespace-only is rejected. |
| description | text, nullable, max 2000 | Optional. `null` means none. | Omitted on create, empty, or whitespace-only is stored as null. Patch may set null to clear it. Omitted on patch leaves it unchanged. |
| completed | boolean, not null, default false | Read-only except via complete and incomplete actions | Create always stores false. Patch cannot change it. |
| created_at | UTC datetime, not null | Read-only | Set once at insert by the application. Never updated. |
| updated_at | UTC datetime, not null | Read-only | Equal to `created_at` on insert. Set by the application only when title, description, or completed actually changes. |

Indexes:

- `todos.owner_id`
- `todos (owner_id, created_at)` to support the list query

List order is `created_at` descending, then `id` descending, expressed in the repository query. It is not an engine-specific index clause.

Duplicate titles are allowed, including across owners and for the same owner. Identity is `id`.

## State

```text
create → incomplete
incomplete → completed     (mark complete; no-op if already completed)
completed → incomplete     (mark incomplete; no-op if already incomplete)
either → deleted           (permanent; id is not reinserted)
```

A no-op complete or incomplete does not change `updated_at`. Delete removes the row. A later write for that id does not insert a new row.

## Ownership queries

Every read and write includes `owner_id` equal to the caller. A row that exists for someone else is treated as missing. List never joins another owner's rows.

## Overlapping writes

The repository applies an update, complete, incomplete, or delete in one transaction and writes only the columns that action changes. The service does not choose a lock or a dialect. The later committed transaction is the stored result for those columns. There is no merge of two request bodies and no conflict error.

## Validation owned by the schema

These checks fail in Pydantic before the service runs, and the stored row is unchanged:

- Missing title on create
- Title empty or whitespace-only on create or patch
- Title longer than 200 characters
- Description longer than 2,000 characters
- Unknown fields, including `completed` and `id`, on create or patch

Clearing a description uses JSON `null` on patch. That is valid and stores null.
