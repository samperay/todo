# Observability Engineering — SRE to Architect

**40 classes · 10 modules · 12 incident scenarios · 3 exercise levels per class**

This is a self-paced, executable workbook built around the FastAPI Todo API on the `feature/prometheus-server-integration` branch of `samperay/todo`. **Start local with Docker Compose; progress to Kubernetes and cloud only after local labs work.**

## How to use this handbook

1. Read [Lab setup](labs/00-lab-setup.md), verify your actual Compose services, and make a separate working branch.
2. Work through modules 01–10 in order. Every class has **theory, guided lab, independent task, incident challenge, review questions, and completion criteria**.
3. Execute labs in a *disposable development environment*. Never use fault injection against a production service.
4. Use [scenario index](scenarios/README.md) to practice diagnosing failures without reading the solution first.
5. Record evidence in `progress.md` and keep changes under version control.

## Existing project assumptions (verify locally)

- FastAPI service `todo-api`, host port 8000, `/metrics` endpoint.
- Prometheus service `prometheus`, host port 9090, scrapes `todo-api:8000` about every 15 seconds.
- Existing metric families: `http_requests_total{method,handler,status}`, `http_requests_in_progress{method}`, and `http_request_duration_seconds{method,handler,status}`.
- `/metrics` is excluded from request instrumentation.

These assumptions reflect our earlier project walkthrough; **this handbook was not generated by checking the live branch**. Paths, authentication requirements, available endpoints, and labels must be checked in your checkout. Some advanced labs require *new* local-only instrumentation and containers; they are not claims about current repository features.

## Safety rules

- Use test data and a dedicated Slack test channel; do not publish tokens or webhooks.
- Bind local service ports to `127.0.0.1` where feasible.
- Put latency injection, forced 5xx responses, and DB failures behind an explicit development-only flag; default OFF.
- Capture a baseline before each experiment; restore the application afterward.
- Kubernetes and cloud work may incur cost; prefer local kind/minikube and document teardown.

## Completion target

At the end you should be able to instrument a service, design useful SLIs, query Prometheus, create dashboards and alerts, investigate incidents using metrics/logs/traces, and explain architecture trade-offs for scale, reliability, and security.
